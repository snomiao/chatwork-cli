# Chatwork CLI Skill

A lightweight Chatwork CLI for reading and sending messages from the terminal,
with a two-step confirm gate so an agent can't fire off a message by accident.

Binary name: `chatwork` (short alias: `cw`).

## When to use

- User wants to read a Chatwork room, tail it, or watch several rooms for new messages.
- User wants to list their Chatwork rooms.
- User wants to send a message to a Chatwork room from the terminal.
- User is setting up the CLI for the first time or hitting an auth / rate-limit error.

## Installation

Requires [Bun](https://bun.sh) (the entrypoint is a TypeScript file run directly by bun).

```sh
# Global install straight from GitHub (creates `chatwork` and `cw` on PATH)
bun install -g github:takusym/chatwork-cli

# …or clone and link for local dev:
git clone https://github.com/takusym/chatwork-cli && cd chatwork-cli
bun install
ln -sf "$(pwd)/ts/cli.ts" ~/.bun/bin/chatwork
ln -sf "$(pwd)/ts/cli.ts" ~/.bun/bin/cw
```

Verify:

```sh
cw --help
```

## First-time setup (get an API token)

The token is stored at `~/.config/chatwork-cli/config.json` (mode 0600).

```sh
# macOS: pick a Chrome profile, scrape the token from token.php automatically
cw login --from-chrome

# …or paste a token you generated by hand:
cw login                       # prompts on stdin
cw login --token=<api-token>   # non-interactive
```

Generate a token manually at:
https://www.chatwork.com/service/packages/chatwork/subpackages/api/token.php

`--from-chrome` lists Chrome profiles, decrypts the chosen profile's chatwork.com
cookies (one Keychain prompt for "Chrome Safe Storage" the first time), then reads
the API token out of the rendered token.php page. If the session has expired, open
Chatwork once in Chrome and retry. **macOS only.**

## Commands

```sh
# List rooms (sorted by last activity); caches rid→name for 5 min so name lookup works
cw rooms
cw rooms --format json

# Read the last N messages of a room
cw read 111111111 -n 20
cw read マイチャット -n 5 --format json

# Tail a room: print the last N, then poll and print new messages (Ctrl-C to stop)
cw tail 111111111 -n 5 --interval 20

# Watch several rooms at once; each line is prefixed with [room_name]
cw watch マイチャット 111111111 "#team"

# Send a message (two-step confirm — see below)
cw send 111111111 "hello"
cw send 111111111 "hello" --code=<code>

# Send with a [To:] mention (account_id or member name, resolved from the room)
cw send 111111111 "確認お願いします" --to Alice          # → prepends [To:100]Aliceさん
cw send 111111111 "ご確認を" --to Alice --to 田中太郎  # repeatable

# Edit an already-sent message (same two-step --code confirm)
cw edit 111111111 <message_id> "訂正後の本文"
cw edit 111111111 <message_id> "訂正後の本文" --code=<code>
```

### `<room>` resolution

`<room>` accepts a numeric `rid`, a bare `<name>`, or `#<name>`. Name lookup tries an
exact match first, then case-sensitive substring against the cached rooms list.
Ambiguous names error out with the candidate rids so you can disambiguate with a `rid`.
So `cw read マイチャット`, `cw read #マイチャット`, and `cw read 333333333` all reach the same room.

> Quote a `#name` in most shells (`"#team"`) — an unquoted `#` starts a comment.

### `send`: read-before-write confirm gate

The first `send` call **does not send**. It previews the room's recent messages (so you
read the context before replying), warns if your text is near-identical to a recent
message (probable re-post), then prints a `--code`. Re-run with that code to actually send.

```sh
cw send 111111111 "hello"
# → --- Last messages in room (rid=111111111) ---------------
#     [2026-07-02 10:31] taku: 先ほどの件、確認しました
#     [2026-07-02 11:05] client: ありがとうございます
#   --- Sending ------------------------------------
#     → room: 111111111 (rid=111111111)
#     Message: hello
#   ------------------------------------------------
#   Re-run within 60s with --code=ab12cd34 to send.

cw send 111111111 "hello" --code=ab12cd34
# → ✓ sent to rid=111111111 (msg_id=...)
```

The preview is best-effort: if the room can't be resolved or its messages can't be
fetched, the gate shows `(room context unavailable)` and still mints the code — a preview
failure never blocks the send. The confirm code expires after 60s; re-run without `--code`
for a fresh preview. **Don't bypass the two-step flow by auto-computing the code — let the
preview be seen first.**

### Don't spam — edit instead of stacking messages

If your own last message in the room was sent within the last 60s, the `send` gate prints
a non-blocking `⚠ 直前(N秒前)に同じルームへ送信しています` warning and suggests `cw edit`.
Prefer consolidating: **edit your previous message** rather than firing a second, third,
fourth message. Combine ack + answer + follow-up into one message when you can. The window
is tunable via `CHATWORK_RESEND_WARN_SECONDS` (`0` disables the warning).

### `--to` mentions

`--to <account_id|name>` prepends a Chatwork `[To:]` mention. A name is resolved against the
room members (exact match first, then substring); an `account_id` is used verbatim. Repeat
`--to` for several people. The mention is part of the confirmed body (shown in the preview,
bound by the `--code`).

### `edit`: fix a sent message

`cw edit <room> <message_id> "<new_body>"` edits a sent message with the same two-step
`--code` confirm. The first call previews the current body next to the replacement. Get the
`message_id` from `read`/`tail --format json` or the `send` success line. Editing is the
right fix for a typo or an omission — reach for it before sending a correction as a new message.

## Rate limits

Chatwork enforces **300 req / 5 min** globally and **10 req / 10s** on message sends.
On a 429 the CLI prints the `x-ratelimit-reset` time so you know when to retry.

## Troubleshooting

- **`command not found: cw`** — the global bin dir isn't on `PATH`. Ensure `~/.bun/bin` is on `PATH`, or re-run the install.
- **Auth / 401 errors** — token missing or revoked. Re-run `cw login --from-chrome` (or `cw login --token=...`).
- **`--from-chrome` finds no token** — the Chrome session expired; open Chatwork once in Chrome, then retry. macOS only.
- **Ambiguous room name** — the CLI lists matching rids; pass a `rid` (or a more specific name) instead.
- **429 rate-limited** — wait until the printed reset time before retrying, especially for bursts of `send`.

## Safety

- The API token in `~/.config/chatwork-cli/config.json` is a credential — treat it like a password; it's written mode 0600.
- The `send` two-step confirm gate is intentional. Don't auto-compute the `--code` to skip the preview; the whole point is to read the room context before sending.
